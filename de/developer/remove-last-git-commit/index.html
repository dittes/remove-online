Den letzten Commit in Git entfernen

Der richtige Befehl hängt von einer Frage ab: Haben Sie den Commit schon gepusht? Beginnen Sie mit den sicheren Varianten.

Noch nicht gepusht: Commit zurücknehmen, Änderungen behalten

git reset --soft HEAD~1

Der Commit ist weg, seine Änderungen sind wieder vorgemerkt (staged). Mit git reset HEAD~1 nehmen Sie sie auch aus der Vormerkung.

Noch nicht gepusht: Commit zurücknehmen und Änderungen verwerfen

git reset --hard HEAD~1

Bereits auf einen gemeinsamen Branch gepusht

Erstellen Sie einen neuen Commit, der den alten umkehrt. Die Historie bleibt für alle erhalten:

git revert HEAD
git push

Nur die Nachricht ist falsch

git commit --amend

Einen gepushten Branch umschreiben, der Ihnen gehört

Nur wenn niemand sonst den Branch nutzt:

git reset --hard HEAD~1
git push --force-with-lease

Achtung: --hard löscht nicht committete Arbeit. Haben Sie versehentlich einen Commit entfernt, listet git reflog die letzten Zustände, und git reset --hard <hash> bringt Sie zurück.

Fragen

Was bedeutet HEAD~1?

Es zeigt auf den Commit vor dem aktuellen. HEAD~3 geht drei Commits zurück.

Warum ist Force-Push riskant?

Er überschreibt die Historie im Remote. Kolleginnen und Kollegen, die den alten Commit schon gezogen haben, bekommen Konflikte.

Verwandte Anleitungen

  • Ein Verzeichnis unter Linux löschen
  • Docker-Images und -Container entfernen
  • Zeilenumbrüche entfernen

Gut zu wissen

Allgemeine Informationen, keine Rechts- oder Fachberatung. Apps ändern ihre Menüs oft; eine Schaltfläche kann in Ihrer Version etwas anders heißen.
